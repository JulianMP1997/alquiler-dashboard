06 · Riesgos

Lo que puede fallar después de la entrega

Un tablero que solo muestra verde no sirve para decidir. Estos son los riesgos que el equipo identificó al corte, con impacto, mitigación, responsable y fecha objetivo.

5 riesgos · 1 alto

R-01 · Sin pipeline de CI/CD

Alto / Medio

Los tests y el build se ejecutan a mano; el deploy a alwaysdata también. Un merge roto puede llegar a producción sin aviso.

Mitigación: GitHub Actions con composer test:unit + npm run build, y bloquear merges si falla. Responsable: Mariano · Fecha: 08/11/2026.

R-02 · Cobertura E2E al 50%

Medio / Alto

Login, publicación, reserva, reseña, mensajería y favoritos no tienen prueba end-to-end. Son los flujos con más riesgo de regresión.

Mitigación: 6 specs Playwright nuevos y smoke test en cada release. Responsable: Julián · Fecha: 15/11/2026.

R-03 · Bus factor = 2

Medio / Alto

Todo el conocimiento está en dos personas. Una ausencia prolongada frena el mantenimiento y el deploy.

Mitigación: ADRs, README de deploy y sesión de handoff cruzado. Responsable: Ambos · Fecha: 30/11/2026.

R-04 · Monitoreo y backups manuales

Medio / Medio

El chequeo de salud es puntual y el hosting gratuito no garantiza backups. No hay alertas si la API se cae.

Mitigación: UptimeRobot + backup MySQL semanal + alerta a Discord/email. Responsable: Mariano · Fecha: 15/11/2026.

R-05 · Pocas pruebas de integración

Bajo / Medio

Solo 4 tests de integración; requieren MySQL y HTTP local. La suite unitaria no detecta problemas de contrato entre capas.

Mitigación: CI con servicio MySQL y al menos 10 tests de integración. Responsable: Julián · Fecha: 22/11/2026.

R-06 · Métricas sin automatizar

Bajo / Bajo

Este tablero se armó con un corte manual. Si no se automatiza, queda desactualizado en una semana.

Mitigación: script semanal que exporte Git + GitHub API + PHPUnit a JSON. Responsable: Julián · Fecha: 22/11/2026.
